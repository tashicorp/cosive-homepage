We have been working on modernising the MISP user interface with responsive web design improvements. The new beta interface is available for users running MISP v2.5.32 or later, and it targets ease of use for analysts working on smaller screens or remotely.

We contributed these changes back to MISP because we actively use and recommend the open-source platform professionally, and we maintain CloudMISP, our enterprise deployment solution. Making MISP better for everyone is part of what we do.

Why change the UI?

Analysts frequently work from portable devices with limited screen real estate. MISP contains substantial valuable data, but the classic design sometimes pushes essential information beyond the visible viewport.

Specific challenges included:

  • Event titles (the Info column) positioned offscreen to the right
  • Frequently accessed action buttons hidden outside the viewing area
  • High information density creating visual clutter

The redesigned interface tackles these concerns through improved layout, reduced visual noise, and reorganised information hierarchy to prioritise what analysts actually need.

Most of the analysts we work with are not sitting at a three-monitor desk. They are on a laptop, in a meeting, trying to answer one question quickly. The interface should meet them there.

Chris Horsley, Principal Security Consultant & CTO, Cosive

How to enable the beta UI

For MISP v2.5.32 or later, enabling the new interface takes three steps:

  1. Navigate to Global Actions
  2. Select the Beta UI button
  3. The interface loads immediately

This setting operates on a per-user basis, so you can try it without affecting anyone else in your organisation. You can switch back to the classic interface at any time.

If you administer MISP and would rather set it from the command line, the equivalent is:

# Per-user setting — no server restart, no effect on other analysts
cd /var/www/MISP/app
sudo -u www-data ./Console/cake Admin setSetting "MISP.ui_beta_enabled" true

What's changed?

1. Reduced information density

The refresh introduces greater spacing and visual breathing room, making content easier to scan and process while retaining all functionality. The goal is to reduce cognitive load without removing the data analysts rely on.

2. Responsive design

The layout intelligently adjusts during browser resizing. Event titles shift leftward for prominence, important context remains immediately visible, and the interface adapts smoothly across different screen dimensions.

This eliminates excessive horizontal scrolling for users working across varied devices — from ultrawide monitors to 13-inch laptops.

3. Action buttons simplified

Previously, action icons lined the right side of event listings. The updated version consolidates actions into a dropdown menu with text labels for each option. This improves discoverability, especially for less frequent users of certain features.

4. Highlight tags for focused visibility

A new column called Highlight Tags surfaces only the tags that matter most to your workflow. Navigate to Tag Taxonomies and select which taxonomy families should receive highlighting.

Only chosen tag categories appear in the column, reducing visual noise while emphasising workflow-critical tags like TLP and Workflow taxonomies.

5. Streamlined top navigation

The left navigation menu underwent hierarchical restructuring, reflecting cognitive science principles about human information processing — specifically, the idea of limiting choices to around seven items at once.

The redesign groups options logically, creates intuitive menu hierarchies, and uses icons for quick category identification. Related features like tags, taxonomies, remote services, and feeds are consolidated. Event creation is more prominent, and import options (STIX, JSON, free text) are easier to access.

Switching back to classic

If you prefer the traditional interface, simply disable the beta UI within your account settings. The change applies only to your account, so teams can run a mix of classic and beta users without any friction.

What's included, and what's next

The current beta covers:

  • Event Listing page — the primary day-to-day view for most analysts
  • Navigation bar — the top-level menu structure

Known limitations

The beta covers the listing and navigation only, so moving into an event drops you back into the classic layout. Saved filters carry across, but column widths do not. Neither is a blocker for day-to-day use, and both are on the list.

We plan to gradually extend the refreshed interface to additional screens, informed by community feedback. The goal is to iterate in the open and contribute improvements back to the broader MISP community over time.

We want your feedback

This is a beta release and it will improve through iteration. If you try the new interface, we would love to hear about:

  • What works well in your day-to-day workflow
  • Any slowdowns or difficulties you encounter
  • Suggestions for further usability improvements

Since MISP is a community-driven project, usability improvements benefit the entire user base. Get in touch with your feedback, or contribute directly through the MISP open-source project.
